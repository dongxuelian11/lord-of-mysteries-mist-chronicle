# 第三阶段：贝克兰德多势力战略竞争

## 目标

第三阶段把贝克兰德从静态控制条改造成持续运行的多方博弈环境。每个自治势力每周都会根据自身目标、资源、敌意、控制现状和战略偏好提交一项宏观行动；玩家即使已经建立分部，其他势力仍会争夺、破坏或巩固关键战略点。

## 借鉴来源与取舍

- [CivRealm](https://github.com/bigai-ai/civrealm)：借鉴标准化的“观察—动作—结算—新状态”环境边界，让势力行动可以测试、复演和后续接入不同模型；不引入 Freeciv 的复杂单位微操。
- [CivRealm LLM baseline](https://github.com/bigai-ai/civrealm-llm-baseline)：借鉴中央顾问统筹多个单位的宏观决策思路；本项目把它收束为势力级战略档案，避免玩家逐个操控基层人员。
- [WarAgent](https://github.com/agiresearch/WarAgent)：借鉴“主体提出行动、秘书审查合法性、关系板记录冲突”的分层；本项目用确定性规则做审查，不额外调用一次模型，防止模型自己批准越权行动。
- [WorldLines](https://github.com/LudicDynamics/WorldLines)：沿用 Plan–Diff–Validate–Apply 和事件溯源思想；战略命令、审查和结果全部进入世界账本，规则先结算，叙事后生成。
- [AI Town](https://github.com/a16z-infra/ai-town) 与 [TinyTroupe](https://github.com/microsoft/TinyTroupe)：持续人物、私人记忆和社会关系主要已在第二阶段吸收；第三阶段不复制高频闲聊循环，以免把组织经营重新拖回人物微操。

## 每周结算流程

1. 为地图中每个非玩家势力补齐持久战略档案。
2. 势力根据教义、目标、资源池、敌意和战略点价值形成命令。
3. 规则审查目标、身份、资源和行动强度；非法命令拒绝，过强命令限幅。
4. 同一战略点上的所有合法命令同时结算，更新多方影响占比和控制状态。
5. 冲突生成外交压力，持续积累为观望、竞争或敌对关系。
6. 玩家情报能力决定只能看到活动痕迹、辨认势力，还是确认完整行动。
7. 可观察信号挂到具体区块和战略点；命令、审查和真实结果进入世界账本。

## 当前规则

- 官方势力偏好权力、安全和信息节点。
- 本地势力偏好市场、交通和社区节点。
- 隐秘势力偏好神秘、信息和社区节点，并会在高敌意时采取破坏行动。
- 行动分为扩张、争夺、巩固和破坏；资源池限制行动强度。
- 地区控制由其区块动态汇总，区块控制由不同权重的战略点动态汇总。
- 建立分部不会冻结控制权；下周其他势力仍会基于当前局势行动。
- 玩家情报人力会直接提高势力辨认能力；战略点的我方存在和情报产出也会提供当地侦测加成。

## 明确不采用的设计

- 不采用单位级移动、路线和战棋微操。
- 不为每个势力命令额外调用“秘书模型”；规则审查必须稳定、可测试。
- 不允许叙事模型改写已经结算的影响、资源和控制结果。
- 不向玩家直接展示未被侦测的势力身份、真实命令或隐藏关系。

## 验收范围

- 每个势力每周至多提交一项结构化战略行动。
- 同一战略点的多方命令可以同时冲突。
- 非法行动会被拒绝，过强行动会被限制。
- 外交压力随争夺和破坏持续变化。
- 低情报玩家只能看到未知活动，高情报玩家能识别或确认行动势力。
- 战略信号能够定位到实际战略点，并被地图和世界账本共同保存。
- v15-v18 存档迁移到 v19 时补齐势力战略状态。
