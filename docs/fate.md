# 命运失控机制（MVP）

## 定位

大成功和大失败必须“非常离谱”，能主动整蛊玩家、扭曲任务、制造长期麻烦或荒谬收益，这是《灰雾纪事》的核心辨识度。

正常能力规则与命运异常严格分离：

```text
玩家确认能力行动
→ 正常能力合法性与规则结算
→ AbilityOutcomeContract
→ 独立命运异常判定
→ FateAberrationContract
→ 两份合同原子应用
→ 世界事件与动态记忆
→ DeepSeek 依据合同叙事
```

能力规则决定原本是否成功、效果多强、正常成本、位阶与反制、普通反噬；命运异常决定宇宙准备怎么拿玩家开玩笑。命运异常不重新塞回 `margin` 公式。

## 独立命运骰

种子：`saveId + resolutionId + "fate-aberration-v1"`。

- 与能力 variance 完全独立（能力种子为结算输入，命运种子绑定 resolutionId）；
- 相同存档、行动与 resolutionId 得到相同命运结果；
- 退出、读档、重启、叙事重写不改变；
- 只有玩家真正改变行动、目标、媒介、准备或风险方案并生成新 resolutionId 才重新判定；
- 不使用 `Math.random()`；算法版本与模板版本进入合同。

## 命运压力

隐藏的 `fatePressure`（0–100）会主动“憋一个大的”：

- 每次符合条件但未触发：+6；
- 高风险行动：+4；强行施展：+8；
- 高污染 +0–10、低稳定 +0–8、越级 +4–12、大型仪式 +6–15（确定性计算）；
- 达到 100 时下一个符合条件的行动必须触发；
- 触发后按严重度下降：一级 −80、二级 −90、三级 −97、四级清零。

> 概率与压力参数经 10 万级分布模拟调参：普通长期路线综合触发率约 5%–10%，高风险路线约 15%–30%，连续未触发最迟 18 次内强制触发一次。

只通过氛围提示（“命运的丝线似乎绷得过紧”等）向玩家表达压力，不显示精确数字。

## 四种交叉结果

| 普通能力结果 | 命运极性 | 实际效果 | twist |
|---|---|---|---|
| 成功 | 极端正面 | 离谱大成功 | `pure` |
| 成功 | 极端负面 | 诅咒式成功 | `cursed-boon` |
| 失败 | 极端正面 | 歪打正着 | `fortunate-disaster` |
| 失败 | 极端负面 | 全面失控 | `full-disaster` |

## 四级严重度

1. 场景荒诞：只影响当前场景或短期状态；
2. 任务扭曲：改变当前任务路线；
3. 长期事故：影响数周、组织或人物关系；
4. 世界线异常：极少发生，可改变长期路线。

四级必须同时满足高风险条件（高压力/大型仪式/高位能力/高污染/世界线偏离），默认 25 周冷却，必须写入世界线偏转记录（`worldKernel.canon`），必须留下恢复或继续经营路径。

## 模板系统

36 个手工模板（每类 9 个：离谱大成功/诅咒式成功/歪打正着/全面失控）+ 4 个确定性安全兜底。模板覆盖感知、占卜、隐匿、精神影响、移动、控制、防御、仪式等家族。

规则引擎只从符合条件的模板中选择；模板选择使用独立确定性种子；近期使用过的模板降权或排除；不允许连续重复同一模板；模板执行失败不重新抽取，使用固定安全兜底。

反无聊审计：每个模板必须有真实“错位”（目标/身份/受众/时间/地点/权威/因果错位、新债务、长期错误信念、新组织关系、新长期计划、世界线偏转、荒谬机会等），并满足 `absurdityScore ≥ 3`、`longTermConsequenceScore ≥ 2`、`recoverabilityScore ≥ 2`；每个模板至少一个恢复/利用/继续经营钩子。

## FateAberrationContract

不可变合同：fateId/resolutionId、算法版本、确定性种子、资格与原因、压力前后、命运骰/极性骰/严重度骰/模板骰、是否触发、极性/twist/严重度、模板、正常能力结果、即时/延迟效果、世界事件与信念/关系/承诺/计划提案、恢复钩子、叙事前提与约束、不变量。

要求：可序列化、可校验、可复现、叙事阶段不可修改、不泄漏玩家无权知道的后台原因；同一 resolutionId 只能生成和应用一次；未触发时也保存最小幂等记录防重骰。

## 合同合并与事务

```text
AbilityOutcomeContract 生成并验证
→ FateAberrationContract 生成并验证
→ 两份合同冲突检查（fail closed）
→ 原子应用正常能力效果
→ 原子应用命运异常效果
→ 写入世界事件与动态记忆
→ 更新命运压力与幂等账本
→ 保存 GameState
→ DeepSeek 生成叙事
```

命运异常不得静默删除正常成本；诅咒式成功保留原成功；歪打正着不得伪装成原目标成功；全面失控不得应用被阻断的原效果。`abilityResolutions` 账本 + 世界事件是双重权威，读档重放结果完全一致。

## 硬门槛与旁路

硬门槛仍然有效：未拥有的能力不生效、序列 9 不能直接控制天使、缺媒介不凭空成功、无效目标不变有效。

但命运可以在旁边“炸出另一件事”：`MISSING_MEDIUM` → 原追踪失败，命运把施术者自己登记成被追踪者。只有真实、已确认、已生成 resolutionId、进入合法性或尝试阶段的行动可进入命运判定；被动状态维护、纯 UI 查看、意图解析、普通错误输入（未拥有能力且无尝试痕迹）不触发。

## 动态记忆与长期后果

每次触发产生高 importance/high emotionalWeight 的 `MemoryEvent`，并按模板产生 `CharacterBelief`、`RelationshipCause`、`Commitment`、`ActivePlan`、组织传闻、错误身份、新债务、恢复任务与世界线偏转。受众隔离、propositionKey、sourceEventId 与幂等语义复用冻结的记忆接口，后台真实原因不自动告诉玩家。

## DeepSeek 叙事边界

模型接收两份合同、场景、授权记忆与 RAG、荒诞前提与明确禁区；负责把事件写得突然、离谱、荒诞，保留神秘、危险与黑色幽默。不得修改模板、增加合同外永久效果、删除长期后果、把诅咒式成功写成纯奖励、把歪打正着写成原目标成功、泄漏模板选择原因、重掷命运。`validateFateNarrative` 校验失败只重写文学文本，不重算合同。

## 命令

```text
npm run fate:audit      # 模板数量/覆盖/反无聊/兜底/种子独立/幂等边界
npm run fate:eval       # 四种交叉/旁路/幂等/重放/压力/受众/兜底
npm run fate:longrun    # 三条 30 周路线（正常经营/高风险疯玩/世界线偏离）
npm run fate:benchmark  # 4×10 万分布模拟 + 2 万合同生成 + 5 千原子应用 + 性能
```

## 接线

- `app/ability-system.ts`：`resolveImmediateAbilityWithEngine` 在能力合同校验后生成命运合同，`applyFateBundle` 原子应用两份合同，叙事校验合并能力与命运约束；
- `app/game-model.ts`：`GameState` 增加可选 `fate` 状态；`createInitialGame` 初始化；
- `app/save-system.ts`：老存档 `ensureFateState` 安全补默认并进入 checksum；
- `app/game-engine.ts`：每周推进时 `advanceFateWeek` 结算到期延迟效果。

## 已知边界（MVP）

- 延迟效果按 `dueWeek` 持久化并在周推演时结算为世界事件与记忆事件；更复杂的分阶段 NPC 行动由后续 UAU 深化。
- 目标/NPC 的“后续提及”目前通过记忆信念/计划验证，尚未接入完整对话生成上下文之外的专门 UI。
- 四级世界线写入更新 `canon.deviation/pivotEventIds/worldlineMode`，但不会重写整条时间线数据。
